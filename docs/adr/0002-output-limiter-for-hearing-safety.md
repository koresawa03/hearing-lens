# ADR-0002: 聴覚保護のため、出力段にピークリミッターと音量上限を置く

- 日付: 2026-11-13
- 状態: 採用

## 背景
聴覚過敏のプロファイルは 3〜4kHz を +15〜18dB 持ち上げる。マイクが急に大きな音（拍手・声）を拾うと、ヘッドホンから非常に大きな音が出て耳を傷める危険がある。
このアプリは聴覚の理解を目的としており、利用者・審査員の耳を傷めることは絶対に避けたい。

## 決定
- 出力段（EQ・リバーブの後）にピークリミッター（`kAudioUnitSubType_PeakLimiter`、`AVAudioUnitEffect` 経由）を置く
- ミキサーの出力音量に上限を設ける
- 開始時は 0 からフェードインする
- 上限値・ブースト量は定数（`FilterParameters` など）にまとめ、実機で聞いて決める

## 検討した他の案と捨てた理由
- 案A: ブースト量を下げるだけにする。捨てた理由: 体験としての「刺さる感じ」が弱くなる。しかもマイクが急に大きな音を拾えば、下げたブーストでも大きな音が出うる。根本対策にならない
- 案B: ユーザーに端末の音量調整を任せる。捨てた理由: 審査員は事前に音量を下げてくれるとは限らない。入力が急に大きくなる事故は音量設定では防げない

## 結果・影響
- 急な大音量から耳を守れる。説明可能な安全設計として、審査・面接でも話せる
- リミッターが働くと音が圧縮されるため、聴覚過敏の「刺さる感じ」が少し減る。ブースト量とリミッターのしきい値を実機で調整する
- 追加の処理ノードが入るが、負荷は小さい

## 追記（2026-11-16）: しきい値を調整するための DynamicsProcessor

### 背景
Apple の `kAudioUnitSubType_PeakLimiter` には、しきい値を決めるパラメータがない（しきい値は 0dBFS に固定で、調整できるのはプリゲイン・アタック・ディケイのみ）。聴覚過敏の +18dB ブーストを実機で聞きながら、「どのくらいの大きさから抑えるか」を詰められない。

### 決定
- リバーブの後・PeakLimiter の前に、`kAudioUnitSubType_DynamicsProcessor` を置く。そのしきい値（出発点 -3dB、調整範囲 -24〜0dB）を調整対象にする
- PeakLimiter は最終の安全装置として残す。音量上限（`absoluteMaxOutputVolume` = 0.6）も変えない

### 検討した他の案と捨てた理由
- 案A: PeakLimiter のプリゲインを調整する。捨てた理由: プリゲインは「しきい値」ではなく入力を増減するだけで、全体の音量感が変わってしまい、「大きい音だけを抑える」調整にならない
- 案B: PeakLimiter をやめて DynamicsProcessor だけにする。捨てた理由: コンプレッサーは、速い立ち上がりの音（拍手など）に対して完全なブリックウォール（上限を絶対に超えない）ではなく、一瞬すり抜けることがある。最終の安全装置は PeakLimiter のままにしたい

### 結果・影響
- 追加ノードは1つで、負荷は小さい。しきい値を実機で詰められる
- 安全の最終ラインは変わらず PeakLimiter と音量上限
